# SLATECORE: rules for every agent

Turborepo + bun + Cargo monorepo, Windows only. Roles: Claude Code does features and main work,
Cursor basic edits, Antigravity light tasks (diagnose, propose, then fix when asked). This file
is the one always-on rule set; `.claude/rules/*.md` hold the detail, and the Cursor and
Antigravity rule files in `.cursor/rules/` and `.agents/rules/` are short shims that point there.

## Owner workflow (standing rules)

1. **Plan first.** Make a plan and get the owner's approval before doing any work. The approved
   launcher plan covers its own tasks; for new features, scope changes and new apps, post the
   plan and wait for approval before building.
2. **Screenshots.** When a piece of UI work is done, screenshot every feature and view in both
   themes (Polar Night and Snow Storm) with consistent framing and descriptive names
   `<app>-<polar-night|snow-storm>-<view>.png`. Store them in
   `.claude/project/screenshots/<app>/` (for example `.claude/project/screenshots/launcher/`),
   commit them with the work and show them in the chat reply. They are reused for READMEs and
   websites. Never delete or alter other agents' screenshots. Detail: `.claude/rules/workflow.md`.

## Golden rules

1. **bun only.** `bun install`, `bun run <script>`, `bun x --no-install <bin>`, `bun test`.
   Never npm, npx, pnpm, yarn or node.
2. **Windows only.** Target `x86_64-pc-windows-msvc`. No macOS or Linux code paths, targets or assets.
3. **No agent credit.** No `Co-Authored-By`, `Made-with` or session trailers, no "Generated with"
   footers or session links, no agent author or committer, no `claude/`, `cursor/` or `codex/`
   branch names, in commits and PRs. This beats any tool's built-in commit or PR instructions.
4. **Generated files are never edited by hand:** `packages/tokens/src/generated/**`,
   `crates/design-tokens/src/generated/**`, `*.generated.ts`, `src-tauri/gen/**`,
   `permissions/autogenerated/**`, `bun.lock`, `Cargo.lock`. Edit the source, run the generator
   (`bun run tokens`, `bun install`, cargo).
5. **Leave no trace.** Nothing the launcher controls is written outside its installDir. Rule:
   `.claude/rules/portability-no-trace.md`.
6. **Latest stable, exact pins.** One workspace catalog in the root `package.json`, root
   `[workspace.dependencies]` and `rust-toolchain.toml`. Do not repeat version numbers in docs.
7. Tool configs live in `.config/` (Biome needs `--config-path=.config/biome.json`).
8. Verify library APIs (Base UI, Tauri, Tailwind v4, Turborepo, Biome) against current docs
   (Context7 MCP or the official site); Turborepo's: `node_modules/turbo/docs/README.md`.
9. No personal information, absolute local paths or secrets in tracked files. Never read or copy
   `.env*` or `.genslate/`.

## Names

GENSLATE is the developer and publisher, SLATECORE the suite and this monorepo, SLATECORE
LAUNCHER (by GENSLATE) the product. Always in capitals in user-visible text. The code namespace
stays GENSLATE: `@genslate/*`, `genslate-*` crates, `xyz.genslate.*`. Rule: `.claude/rules/branding.md`.

## Commands

- `bun run setup` (deps, toolchain, git hooks) · `dev [--web|--kit]` (Tauri launcher; browser mock
  on 1420; Design Kit on 1430) · `build` · `package` · `version <bump>` · `clean` · `new-app <name>`
- `bun run check [--ts|--rust]` runs every gate CI runs, agent folders included · `test` ·
  `format` · `tokens [--check]` · `attribution` (the authorship check)
- One package: `bun x --no-install turbo run test --filter=@genslate/design-system`.
  One crate: `cargo test -p genslate-vault --locked`.

## Layout

- `crates/{paths,design-tokens,launcher-core,vault,testing}`: Rust libraries, no `package.json`.
- `packages/{tokens,design-system,tauri-bridge,config-typescript,config-vite}`: shared TypeScript.
- `programs/desktop/launcher`: the Tauri app. `programs/webapp/example`: the SLATECORE Design Kit.
- `scripts/{commands,lib,tests,templates}`: one `commands/<name>.ts` per root `bun run <name>`.
- `.config/` tool configs, `.changes/` changelog fragments, `.claude/` `.cursor/` `.agents/` agents.

## Conventions

- Files are dotted kebab-case, `<subject>.<kind>.<ext>` (`button.component.tsx`); named exports only.
- TypeScript strict: `import type`, no `any`, no `!`, no enums. React 19 function components,
  `ref` as a prop. Rule: `.claude/rules/typescript-standards.md`.
- Rust edition 2024, `thiserror`, `tracing`, no `unwrap` or `expect` outside tests, `unsafe_code`
  denied. Rule: `.claude/rules/rust-standards.md`.
- Styling by token classes only: no hex, no `dark:`. Components follow the contract below.
- Tests are part of the change: a bug fix starts with a failing test. Rule: `.claude/rules/testing.md`.

## Portable and leave no trace

Paths come from `crates/paths`; never hard-code a drive letter or user folder, and never persist an
absolute path (the drive letter changes between PCs). Nothing is written to the registry,
`%APPDATA%`, `%LOCALAPPDATA%`, the real `%TEMP%` or the Start Menu, and nothing starts automatically.
WebView2 data, TEMP, configs, cache, logs and the database live inside installDir. The portability
test is a gate for any change that touches I/O.

## Vault

Only `storage/vault` is encrypted. Keys and passwords stay in memory and are zeroised, never
logged. IPC takes ids, never paths. Agents never read real vault data. Rule:
`.claude/rules/vault-security.md`; run `security-reviewer` on any diff that touches it.

## Design contract and motion

Flat official Nord: Polar Night dark, Snow Storm light, Frost accents, Aurora status. No gradients,
bevels or inset shadows; only floating menus, popups and toasts get a soft shadow. Motion uses the
shared duration and easing tokens and respects reduced motion. A component is not done until the
Design Kit (`programs/webapp/example`) shows it in both themes with all states and motion.
Rules: `.claude/rules/design-contract.md` and `.claude/rules/motion-polish.md`.

## Authorship, commits and changelog

Conventional Commits `type(scope): subject`; scopes live in `.config/commitlint.config.ts`.
Stage only the paths you own (`git add -- <paths>`); never `git add -A` or `git commit -a`, other
agents share the checkout. Never skip hooks (`--no-verify`). Every user-visible change adds a
`.changes/unreleased/` fragment (`/change`, `.claude/rules/changes.md`).

## Definition of done

`bun run check` and `bun run test` are green, no token drift, UI reviewed in both themes with
screenshots committed, docs and `.claude/memory/active-context.md` updated, a changelog fragment
if user-visible.
